# 04 — I2P SAM v3

## Goal

Core-shaped `-i2psam`: the node dials and learns BIP155 I2P peers through a
system I2P router’s SAM v3 TCP port (default `127.0.0.1:7656`). Optional
incoming: a persistent local destination forwarded to the P2P loopback
port. `--onlynet=i2p`. No Arti, no SOCKS (SAM is a different protocol).

## Constraints

- Depends on **02** (`NetAddr` + `--onlynet` + peers v2).
- Fake SAM in unit tests. No live I2P router in CI.
- Outbound: `HELLO VERSION`, `SESSION CREATE`, `STREAM CONNECT` (not SOCKS).
- `NetAddr::I2p` — 32-byte destination + port; persist in `peers` v2.
- Fail start if `onlynet` includes i2p and `--i2psam` is unset.
- Wallet I2P destinations wait for [05](./05-wallet-onion.md) if STREAM
  FORWARD is the same helper; this PR is P2P-first. If FORWARD is identical
  to incoming P2P, a last step may add a P2P-only destination and leave
  Electrum/Esplora ports to 05.

## Out of scope

Tor, CJDNS, Electrum/Esplora I2P unless the forward helper is already
written for P2P incoming and wiring a second port is a few lines (then do
it in 05, not here).

## Steps

### Step 1 — `NetAddr::I2p` parse / AddrV2

- **Contract:** `NetAddr::I2p { dest: [u8; 32], port }`. Round-trip
  BIP155 `AddrV2::I2p`. Display is the I2P base32 destination form Core
  uses (or a documented hex if rust-bitcoin already has a formatter — match
  rust-bitcoin / Core, do not invent a third encoding).
- **Red:** `netaddr_i2p_addrv2_roundtrip`.
- **Green:** extend `NetAddr` from 02.
- **Refactor:** keep onion/ip arms untouched.
- **Verify:** `cargo test -p rbitcoin-net netaddr_i2p`
- **Done when:** the [cycle](../how-we-plan.md#the-cycle-red--green--refactor) closed and the slice is committed

### Step 2 — Fake SAM STREAM CONNECT

- **Contract:** SAM client `HELLO` / `SESSION CREATE` / `STREAM CONNECT`
  to a destination; fake SAM accepts and splices to a local TCP peer
  (or returns a connected stream). Bad HELLO is error.
- **Red:** `cargo test -p rbitcoin-net i2p_sam_stream_connect_fake`.
- **Green:** `i2p_sam.rs` in `rbitcoin-net` (dial is net’s job).
- **Refactor:** session reused for multiple STREAM CONNECTs (one SESSION
  per process).
- **Verify:** `cargo test -p rbitcoin-net i2p_sam_`
- **Done when:** the [cycle](../how-we-plan.md#the-cycle-red--green--refactor) closed and the slice is committed

### Step 3 — `learn_addrv2` + persist I2P

- **Contract:** `AddrV2::I2p` is learned. Peers file v2 round-trips I2P
  rows. Without `--i2psam`, I2P entries may load but are not dialed.
- **Red:** `learn_addrv2_keeps_i2p`; `peers_file_roundtrip_i2p`.
- **Green:** `learn_addrv2` arm; persist encoder.
- **Verify:** `cargo test -p rbitcoin-net learn_addrv2` ;
  `cargo test -p rbitcoin-net peers_file_`
- **Done when:** the [cycle](../how-we-plan.md#the-cycle-red--green--refactor) closed and the slice is committed

### Step 4 — `--i2psam` / `--onlynet=i2p` / start fail

- **Contract:** `--i2psam [HOST:PORT]` default `127.0.0.1:7656` when flag
  present with omitted ADDR. `--onlynet=i2p` is valid. `--onlynet=i2p`
  without `--i2psam` is Config error. Dialer uses SAM for `NetAddr::I2p`.
- **Red:** `i2psam_cli`; `onlynet_i2p_without_sam_is_config_error`;
  `dial_i2p_uses_sam`.
- **Green:** node flags; Dialer I2P arm.
- **Refactor:** `--onlynet` parser from 02 grows `i2p`, not a second flag
  dialect.
- **Verify:** `cargo test -p rbitcoin-node i2p_` ;
  `cargo test -p rbitcoin-net dial_i2p`
- **Done when:** the [cycle](../how-we-plan.md#the-cycle-red--green--refactor) closed and the slice is committed

### Step 5 — Optional `--i2p-accept-incoming`

- **Contract:** when set, create/persist a local destination
  (`{datadir}/i2p/p2p.priv` or SAM `SIGNATURE_TYPE` persistent session) and
  STREAM FORWARD / accept to the P2P loopback listener. If `--listen=0`
  (01), incoming I2P still needs a loopback P2P accept (same pattern as 07):
  bind `127.0.0.1` for overlay only, or refuse incoming with a clear error
  until a loopback bind exists.
- **Red:** `i2p_accept_incoming_forwards_to_loopback` against fake SAM.
- **Green:** flag; persist; FORWARD. If loopback bind is too entangled with
  07, **refuse incoming when no P2P listener** with Config error naming
  `--listen` or wait-for-07 — document the choice in OPERATOR. Prefer
  loopback bind here if 01 already allows a tagged bind.
- **Refactor:** do not duplicate P2P accept loop.
- **Verify:** `cargo test -p rbitcoin-node i2p_accept_`
- **Done when:** the [cycle](../how-we-plan.md#the-cycle-red--green--refactor) closed and the slice is committed

### Step 6 — OPERATOR + NixOS module

- **Contract:** `--i2psam`, `--i2p-accept-incoming`, `--onlynet=i2p`, no
  live router in CI. Module: `i2p.sam`, `i2p.acceptIncoming`;
  `After`/`Wants` `i2pd.service` when SAM is set. Eval asserts argv.
  Extend runtime test; label **`nixos-module-runtime`**. Do not start i2pd
  in CI.
- **Red:** eval assert for `--i2psam`.
- **Green:** module + eval + runtime test + OPERATOR P2P networks paragraph.
- **Verify:** `nix build .#checks.x86_64-linux.nixos-module-eval --no-link`;
  grep OPERATOR. Poll `--interest nixos-module-runtime`.
- **Done when:** the [cycle](../how-we-plan.md#the-cycle-red--green--refactor) closed and the slice is committed

## Test budget

Fake SAM only. No Java I2P / i2pd in CI.

## Risks / follow-ups

SAM versions (3.1 vs 3.2) and DESTINATION encoding must match what Bitcoin
Core peers send on addrv2. Wallet STREAM FORWARD is 05.
